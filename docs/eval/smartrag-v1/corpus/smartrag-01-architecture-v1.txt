SmartRag 当前架构与存储职责（评测资料 v1）
资料范围：描述当前 SmartRag 仓库的实现，不代表性能承诺。配置项有默认值和环境覆盖两个层次；版本来自代码或构建配置，不能当成所有部署环境都相同。

技术栈与依赖
SmartRag 后端使用 Java 17 和 Spring Boot 3.4.2，构建与依赖管理使用 Maven。业务实体通过 Spring Data JPA 持久化到 MySQL。前端采用 Vue 3 和 TypeScript，构建工具为 Vite，界面组件使用 Naive UI，前端包管理器使用 pnpm。浏览器发送请求到后端 API，开发模式可以通过 Vite 的代理转发，前端端口与 API 端口属于两个独立服务。

原始文件与数据库
MinIO 保存原始文档对象。MySQL 保存用户、文件上传记录、文档分块等业务数据。文档内容切分后，需要生成向量并写入 Elasticsearch 检索索引。MinIO 对象上传成功不能证明 Elasticsearch 索引完成；MySQL 中有文件记录也不能证明每个分块都完成向量化。三者分工不同，排查时应分别确认对象、业务状态与可检索内容。

搜索引擎与索引
当前知识检索使用 Elasticsearch 同时保存分块正文和 dense_vector 向量。混合检索的关键词分支和向量分支都使用 Elasticsearch。检索入口是 HybridSearchService.searchWithPermission，不应仅因为仓库还保留 Milvus 依赖或历史代码，就认定当前问答查询一定要访问 Milvus。判断实际链路要看正在被调用的方法，而不是把所有依赖名称都算成运行架构。

异步处理
Kafka 承接文件处理任务，将上传请求与解析、分块、向量化解耦。上传接口完成不表示解析过程已经结束；用户需要等待异步处理，再检查索引与检索结果。前端的上传进度通常反映数据传输情况，不能直接当作知识库处理完成百分比。异步解耦改善请求组织方式，但本资料没有给出固定吞吐量或可靠性 SLA。

缓存与问答
Redis 参与缓存、配额和对话相关的短期状态管理。MySQL 是业务持久化存储。聊天入口还涉及 WebSocket 流式响应和 ReAct 工具调用，因此“能登录”“WebSocket 已连接”“能检索文档”是不同层次的检查。某个层次正常不代表其他层次自动正常。评测只覆盖固定题目的一次检索和生成，不等于完整覆盖所有对话行为。

部署配置的边界
Spring 配置可以由环境变量覆盖。文件中声明的默认端口、分块参数或模型参数不是线上当前值的证明。对比两轮实验时，应固定测试集、账号、模型与 TopK，并记录所改变的因素。不能将本地单机实验结果解释为在任意机器、任意规模文档上都成立的性能指标。
