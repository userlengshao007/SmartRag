SmartRag 身份认证与文档访问（评测资料 v1）
本资料区分登录认证、菜单权限和文档可见性。访问后台评测页面需要管理员身份，但后台评测仍使用登录用户的文档访问身份执行检索。

角色与管理员接口
系统用户角色包括 ADMIN 和 USER。评测接口位于 /api/v1/admin/eval，属于 /api/v1/admin/** 管理员路径，普通用户不能因为知道 URL 就合法访问。前端路由也限制 ADMIN 角色，但真正的 API 权限控制由后端安全配置实施。只隐藏菜单不能代替后端鉴权。

文件级过滤
文档权限条件在检索请求中约束候选范围。主要条件涉及上传者 userId、组织标签 orgTag 和公开标记 isPublic。公开文档、本人文档及与有效组织标签相符的文档是不同可见性来源。关键词召回和向量召回都应带上权限过滤；不能先把所有私有内容召回给模型，再仅在前端隐藏引用。被隐藏的引用并不代表正文从未进入模型。

评测使用的身份
管理员发起评测时，控制器从 JWT 提取用户身份，传给带权限检索入口。生成与评委可以使用 system-eval 请求方标记，但该标记不等于搜索绕过文件权限。配额调用身份与文档检索身份是不同概念。比较结果时必须固定账号和组织标签，否则同一问题可见的资料范围可能不同。

私有资料的测试边界
若要测试私有文档，应使用有权读取资料的账号执行正向用例，再使用无权账号做单独的权限用例。单纯在一个管理员账号下运行一组公开文档题，不能证明租户隔离已完整通过。这个评测资料包建议统一用当前管理员可访问的公开文件跑质量基线，不把权限隔离覆盖率混进命中率指标。

登录与密码
账号密码验证由 UserService 调用 PasswordUtil.matches，将输入密码与数据库密码哈希比较。密码哈希不是可逆密文，不能从数据库记录直接读出原始登录密码。项目 admin 登录密码、MySQL root 密码和模型服务 API Key 属于不同凭据，互换使用不会获得正确登录结果。测试资料不包含真实密码或密钥，也不应要求模型返回这些秘密。

故障定位
登录失败需要区分前端校验、后端认证和服务不可达。数据库连接失败与用户密码错误不是同一种故障。一个账号能登录，但看不到某份资料，应核对文件所属用户、组织标签与公开状态。不要通过把所有文件改成公开来掩盖权限问题；应先明确资料本来应该允许哪些用户访问。

标注与隐私
expectedFileNames 可以写期望文件名，但文件必须对当前身份可见。标注了一个不可见文件会造成题目未命中，这不是算法召回不足的充分证据。报告包含问题、回答和检索正文，应按资料本身的访问级别保管。下载报告是为了复核，不意味着原始私有文档自动变为公共数据。
