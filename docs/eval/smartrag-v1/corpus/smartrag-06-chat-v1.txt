SmartRag 问答、工具与引用（评测资料 v1）
本资料讨论模型回答如何获得证据，以及离线评测与完整聊天产品之间的边界。模型能组织语言不等于已经查到了知识库中的真实依据。

ReAct 工具
AgentToolRegistry 注册 search_knowledge、generate_summary、submit_feedback、knowledge_stats 四类工具。search_knowledge 查询当前用户能访问的知识分块；generate_summary 检索相关资料并生成摘要；submit_feedback 用于记录反馈；knowledge_stats 用于查询知识库统计。工具名字代表具体后端能力，不应把统计结果当作文档原文，也不能把一条用户反馈当成检索证据。

问答证据
回答需要基于实际检索片段，并保留来源编号。模型若没有获得足够资料，应说明资料不足，而不是用语气肯定的长回答弥补证据缺失。引用编号是指向本轮提供的资料，不是自动证明整段回答每个句子都正确。人工核查时，仍需要检查引用片段是否支持相应结论。

消息构造
离线评测调用 buildRagMessages 复用在线 RAG 的提示词规则和引用边界。评测输入包含题目和检索上下文，回答模型不接收参考答案。生成完成后，参考答案才随实际回答和证据一起发送给评委。若把参考答案提前放进回答模型的输入，测到的就不再是独立问答能力。

流式体验
聊天通过 WebSocket 展示流式输出。页面能持续出现文字，只能证明交互链路正在返回内容，不能替代正确性判断。文本生成结束、引用有效、事实正确、资料可见，是需要分别检查的维度。网络连接中断也不应直接被解释为模型能力下降，应该先排查客户端和后端连接状态。

离线评测覆盖范围
当前离线评测是固定题目的一次检索、一次回答和一次评委判断。它没有完整执行聊天 Agent 的多轮工具选择，不覆盖历史压缩、长期记忆、复杂的追问或全部工具组合。离线准确率高不代表整个聊天产品的所有交互已经验证；它适合用作检索与单轮回答质量的回归基线。

未命中却答对
当标注说未命中而评委判对时，可能是其他证据也支持答案，可能是证据标注不完整，也可能是模型已有知识或评委过于宽松。这类结果应进入人工复核，不能立即宣布检索已经没有价值。只有仔细对照实际片段和参考答案，才能确认答案是有依据的还是碰巧说对。

知识更新
修改文档以后，旧引用或旧分块编号可能已经无法反映新索引内容。新报告会保存当时送给模型的证据文本，便于以后检查生成时究竟看到了什么。报告只是一次实验快照，不自动让历史答案与最新资料同步。真正需要最新结论的问题，应在更新索引后重新执行检索和生成。
