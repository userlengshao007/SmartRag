# SmartRag 50 题基线资料包 v1

这套资料参考原 smartPai 测试集的题型设计，按当前项目实现重新编写。它用于建立可重复的本地 RAG 基线，不是原项目测试集的原样移植，也不能用来证明通用生产准确率。

## 文件与上传顺序

1. 打开知识库，上传 `corpus/` 下的 **全部 10 个 TXT 文件**，保持文件名不变。统一使用同一管理员可检索的权限范围；质量基线建议设置为公开。等待全部解析、向量化处理完成，再搜索其中一段辨识度高的原文确认入库。
2. 打开「RAG 评测」→「新建评测」，上传同目录的 **`smartrag-eval-50-v1.jsonl`**。预览应显示 50 题，其中 44 题有检索标注。先选仅检索模式、TopK=5，命名为 `v1-检索基线`。
3. 再运行完整评测，命名为 `v1-完整基线`。查看命中率、MRR、准确率、失败数与逐题证据。对未命中却判答对的题、回答错误题进行人工复核。完整模式会产生 Embedding、生成与评委调用费用。

**不要将 JSONL、README 或 manifest 上传到知识库**：它们包含题目、标准答案或标注元数据，会造成答案泄漏。知识库只上传 `corpus/` 中的 TXT。外层 ZIP 需要先解压，不能把 ZIP 当成一篇知识文档直接上传。

旧的 `smartrag.pdf` 可以保留作为额外背景资料，但不再是这套题的期望文件。之前的样例测试集只有 3 题，请不要继续拿它当本套正式测试集。新题采用文件名精确标注，改名后必须同步更新 JSONL。

## 50 道题的分布

| 题号前缀 | 数量 | 检查目标 |
| --- | ---: | --- |
| fact | 18 | 单点事实与参数，不同职责和配置单位 |
| para | 12 | 口语化改写、术语变化、边界条件解释 |
| multi | 8 | 多段或跨文档综合，答案要覆盖多个要点 |
| boundary | 6 | 干扰系统、当前与未接入能力、相近数字的辨析 |
| neg | 6 | 未披露的延迟、SLA、财务、成本、固定收益与全量准确率，应该说明无法确认 |

44 道正向题都标注了期望文件与原文证据短语。6 道无答案题不标注期望文件，不进入检索命中率分母，但参与完整模式的回答评分。

## 已做的校验与未做的实验

自动校验使用项目的 `EvalDatasetParser`、Apache Tika、`ParseService` 当前 fixed 分块（512 字符、10% overlap）以及 `RetrievalMetrics.isRelevant`，确认：

- 恰好 50 题，id 唯一、必填字段齐全；44 道正向题均有证据标注。
- 期望文件都存在；抽取和分块后，每道正向题的每份期望文件仍至少有一个可匹配证据块。
- 10 份源资料均可形成多个块，总块数至少 25，明显多于原先的一块简介；这不等于索引已完成，实际入库仍以运行环境为准。
- 可上传 JSONL 与内置 `classpath:eval/smartrag-eval-50-v1.jsonl` 内容一致。

校验不调用 Embedding、不访问搜索服务、不调用回答模型，不代表实测命中率或准确率已经达标。尚未将这些新资料上传到你的运行中知识库，也没有替你触发付费评测。

## 解释结果时的限制

1. 当前 recallAtK 实际是题目级 Hit Rate@K：任意一条相关证据出现就算命中。多证据题即使标注多份文件，也不要求所有文件或所有短语全部返回。请结合文档覆盖率、逐题结果和回答完整性判断。
2. 这是一套按代码整理、人工编写的起步回归集。题目与资料来自同一次整理，覆盖也集中在项目技术说明；结果可能比真实用户问题乐观。以后应补充真实使用中的失败问题和未见过的文档。
3. 概念辨析题包含相似干扰主体，但没有把尚未实现的 rerank、父块扩展或上下文说明伪写成已实现功能。
4. 不同账号可见资料不同；既有知识库中的其他资料也可能提供答案。运行期间尽量固定账号、资料、模型、TopK，修改一个因素后再比较。
5. 无答案题不能依赖“结果返回为空”来定义成功。即使返回了相似资料，只要资料不足，回答也应明确说无法确认。
6. 评委与生成目前共用激活的模型，自动评分可能偏宽松。题库不是自动评分可信度的保证，仍需抽样人工复核。

## 维护

资料和可上传题库以 `docs/eval/smartrag-v1/` 为准，内置题库是同内容副本。修改后同步更新 `src/main/resources/eval/smartrag-eval-50-v1.jsonl`，运行 `RagEvalCorpusTest` 检查文件名与分块证据没有失配，再更新 manifest。
